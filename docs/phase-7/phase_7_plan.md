HLD: Energy Grid & Power Distribution System

Status: Draft / Architectural Specification
Author: Systems Architect
Scope: Real-time power balancing, player-driven throttling, proportional brownouts, and grid geometry.

1. Abstract

The "Cave" hivemind operates on a symbiotic energy grid where power (Body, Mind, Social) is generated by the population and consumed by "Station" nodes. This document defines a proportional distribution system where supply deficits are shared equally across all active consumers. It also defines a geometric visual logic where the width of power lines represents their fraction of total grid draw.

2. Core Mental Model

2.1 The Grid as a Shared Pool

Energy is a continuous flow from Pools to Demand Nodes.

Pools (Sources): Aggregate attributes from the Swarm and Faces (facilitated by the AttributePoolSystem).

Demand Nodes (Sinks): Consumption points (e.g., the Hearth requires Mind/Body power).

Proportional Diminishment: If the total power requested by all nodes exceeds the pool supply, every node's performance is scaled down by the same percentage (Brownout).

Player Control (Throttling): The player manually adjusts a "Throttle" (0.0 to 1.0) on each node. This determines the percentage of the node's maximum potential demand it actually attempts to draw from the grid.

3. Data Structures

3.1 New Components

PowerSourceComponent

Applied to Pool entities (e.g., pool_body).

{
"attribute": "body" | "mind" | "social",
"availablePower": number,
"gridId": "string"
}

PowerSinkComponent

Applied to Station entities.

{
"baseDemand": {
"body": 10,
"mind": 5
},
"throttle": 0.8, // Player-controlled (0.0 to 1.0)
"efficiency": 0.0, // Calculated per tick (0.0 to 1.0)
"drawFraction": 0.0, // (Node Demand / Total Grid Demand)
"status": "nominal" | "brownout" | "blackout"
}

4. System Architecture: EnergyDistributionSystem

4.1 Step 1: Demand Calculation

The system queries all entities with a PowerSinkComponent. For each attribute:

Calculate Actual Requested Demand ($D_{node}$): node.baseDemand \* node.throttle.

Calculate Total Grid Request ($D_{total}$): Sum of all $D_{node}$.

4.2 Step 2: Proportional Distribution & Fractions

For each attribute (Body, Mind, Social):

Get TotalSupply ($S_{total}$) from the Pool.

Calculate Grid Efficiency: $Min(1.0, S_{total} / D_{total})$.

For each node, calculate Draw Fraction: $F_{node} = D_{node} / D_{total}$.

Apply results:

node.efficiency = GridEfficiency.

node.drawFraction = F\_{node}.

Status Update:

Nominal: efficiency >= 0.99.

Brownout: efficiency < 0.99 AND efficiency > 0.0 (Insufficient supply).

Blackout: efficiency == 0.0 (Zero supply or throttle).

5. Visual Geometry: Proportional Line Widths

To make grid load legible, the physical width of the veins is driven by the Draw Fraction, constrained by the size of the source Pool.

5.1 The Total Width Constraint

The total width of all outgoing power lines for an attribute must equal the current diameter of that attribute's Pool node ($Dia_{pool}$).

5.2 Node Line Thickness Calculation

For any given connection between a Pool and a Sink:

$Width_{line} = Dia_{pool} \times node.drawFraction$.

Example:

Mind Pool diameter is 100px.

Hearth requests 10% of total Mind draw ($F_{node} = 0.10$).

Hearth Vein width = 10px.

Research Table requests 90% of total Mind draw ($F_{node} = 0.90$).

Research Table Vein width = 90px.

6. Gameplay Mechanics

6.1 Manual Throttling

The player manages "Brownouts" by reducing the throttle on non-essential nodes. Reducing a node's throttle:

Reduces its $D_{node}$.

Reduces the $D_{total}$ of the grid.

Increases the shared efficiency for all other nodes.

Visually: The vein for the throttled node gets thinner, while others get thicker (as they now represent a larger fraction of the reduced total).

6.2 Feedback Loop

Thickness: Indicates what percentage of the "Work" this node is responsible for.

Pulse/Color: Indicates "Health" (Nominal vs Brownout).
