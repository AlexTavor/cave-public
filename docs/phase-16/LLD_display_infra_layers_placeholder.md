# LLD — Display Infrastructure + Placeholder Renderers + Layers (EffectsBus Deferred)
**Project:** Cave  
**Scope:** Implement world-space display infrastructure that:
- associates runtime entities with visual instances via `DisplayComponent.display_key`,
- composes each display instance from an explicitly configured module stack,
- supports multiple render layers and per-entity anchors that are **not** children of the entity root,
- uses typed pooling (generic pool + per-display-key pool sets),
- renders monochrome placeholder shapes via key-based texture rules,
- supports particles as a composable module (heat and xp),
- integrates pulse by providing `pulseValue` in tick context (no registration model),
- completes `transferScene* → gameScene*` renames for the world scene and associated helpers.

**Explicit non-scope:** EffectsBus is not implemented in this LLD. Standalone, TTL-based, cross-entity/global effects will be added later.

This LLD contains **no code**. Pseudocode is used only where it removes ambiguity.

## 1. Why

### 1.1 Lifecycle
World rendering must be deterministic and centrally managed. We need a single mechanism that:
- determines render eligibility from the DisplayComponent,
- creates one instance per eligible entity,
- ticks it each frame,
- destroys it when entity disappears or becomes ineligible.

### 1.2 Composition
Displays are composed behavior units. Module selection and ordering must be **per display definition**; there are **no globally mandatory modules** and **no globally mandatory ordering**.

### 1.3 Layers and anchors
Some visuals must live in global layers (background, effects, overlays) and must not necessarily be children of the entity’s root container. We need a comfortable, extensible, injectable approach that:
- centralizes layer creation and ordering,
- allows modules to attach objects to different layers,
- supports entity-following “anchors” in those layers (not parented under root).

### 1.4 Placeholder viability
Before final assets exist, placeholders must be distinct for dozens of display types. Placeholders must be driven by `display_key` so later replacements do not change lifecycle plumbing.

### 1.5 Pulse is core; modules are dumb
Pulse must be available to modules. Modules are “dumb functions” operating on Phaser objects; tick context supplies all required data. Therefore:
- PulseEngine is sampled once per entity per tick.
- `pulseValue` is passed in tick context.

No pulse registration/listener model exists in this design.

## 2. What (Definition of Done)

1) **DisplayComponent rename**
- Replace `DisplayComponent.icon` with `DisplayComponent.display_key` across schema, compiler, runtime, UI, and tests.

2) **Eligibility rule**
- Entity has a visual instance IFF a valid DisplayComponent resolves (entity overrides blueprint) and `display_key` is a non-empty string.

3) **LayerRegistry**
- GameScene owns a typed `LayerRegistry` that creates and exposes fixed world layers with explicit ordering.

4) **Anchors**
- Every entity visual instance owns these containers (all pooled; none are children of each other):
  - `root` (Entities layer)
  - `backgroundAnchor` (Background layer)
  - `effectsAnchor` (EffectsAnchored layer)
  - `overlayAnchor` (Overlays layer)

5) **Module composition**
- Each `display_key` resolves to a `DisplayDefinition` containing an ordered `moduleStack` (0..N module factories).
- No module is obligatory.
- Ordering is per definition.

6) **Pooling**
- There is a generic typed pool implementation.
- There is a pool set per `display_key` that provides pooled containers/images/particles managers used by instance modules.
- Pools are released deterministically on instance destroy and on runtime unload.

7) **Monochrome texture rules**
- TextureManager generates **white-on-transparent** textures only.
- No per-texture colors or tints exist in the placeholder pipeline.
- Each texture key is generated by its own rule class.

8) **ParticlesModule**
- A composable ParticlesModule exists.
- Initial supported kinds: `heat`, `xp`.
- It takes:
  - `kind: "heat" | "xp"`
  - `particleTexture: TextureKeys`
  - `placement: "anchored" | "global"`
- It uses a typed per-kind resolver to obtain Phaser emitter config.
- It reads intensity values from entity state in an explicit, typed way (see §10.6).

9) **Pulse in context**
- Tick context contains `pulseValue: number` computed by PulseEngine for this entity and tick.
- Any module may use it.

10) **Rename completion**
- World scene and helper modules are fully renamed from transferScene* to gameScene* with no remaining “transferScene” naming for world display code.

11) **Tests**
- Unit tests cover: eligibility resolution; display registry resolution; pool behavior; placeholder variant selection; transform propagation to anchors; particles config selection; lifecycle create/tick/destroy; negative paths and edge cases.

## 6. Layers and Anchors (Comfortable, Extensible, Injectable)

### 6.1 Add: `src/engine/phaser/display/layers/LayerIds.ts`
**Responsibility:** Define the authoritative set of world layer ids.

**Type**
- `enum LayerId` with exactly:
  - `Background`
  - `Entities`
  - `Overlays`
  - `EffectsAnchored`
  - `EffectsGlobal`

No other layers exist in this LLD.

### 6.2 Add: `src/engine/phaser/display/layers/LayerRegistry.ts`
**Responsibility:** Own creation and retrieval of layer containers in GameScene.

**Interface**
- constructor `(scene: Phaser.Scene)`
- `get(id: LayerId): Phaser.GameObjects.Container`
- `destroy(): void` (destroys all layer containers; idempotent)

**Ordering rule (unambiguous)**
The registry MUST assign explicit `depth` values to ensure consistent draw order:
- Background: depth 0
- Entities: depth 10
- Overlays: depth 20
- EffectsAnchored: depth 30
- EffectsGlobal: depth 40

Each layer container is created once in `GameScene.create()` and never recreated until scene shutdown.

### 6.3 Anchor model (instance-owned, cross-layer)
Every EntityVisualInstance owns these pooled containers, each parented under a specific layer container:
- `backgroundAnchor` parent: LayerRegistry.get(Background)
- `root` parent: LayerRegistry.get(Entities)
- `overlayAnchor` parent: LayerRegistry.get(Overlays)
- `effectsAnchor` parent: LayerRegistry.get(EffectsAnchored)

None of these anchors are children of each other.

## 7. Core Display Types (Typed; No unknown; No ambiguity)

### 7.1 Add: `src/engine/phaser/display/types.ts`
**Responsibility:** Define all typed interfaces for display infrastructure.

#### 7.1.1 DisplaySpec
Fields:
- `entityId: string`
- `display_key: string`
- `label: string`
- `styleId: string | null`
- `hasPhysics: boolean`
- `x: number`
- `y: number`
- `radius: number`

Sentinel rule:
- if `hasPhysics` is false, then `x=y=0` and `radius=0`.

#### 7.1.2 DisplayScratch
Typed mutable storage for Phaser object references owned by the instance/modules.

Fields:
- `root: Phaser.GameObjects.Container`
- `backgroundAnchor: Phaser.GameObjects.Container`
- `effectsAnchor: Phaser.GameObjects.Container`
- `overlayAnchor: Phaser.GameObjects.Container`

Optional object slots (module-owned; null when absent):
- `backgroundImage: Phaser.GameObjects.Image | null`
- `mainImage: Phaser.GameObjects.Image | null`
- `particlesManager: Phaser.GameObjects.Particles.ParticleEmitterManager | null`
- `particleEmitter: Phaser.GameObjects.Particles.ParticleEmitter | null`

#### 7.1.3 Context types
`DisplayInitContext`:
- `scene: Phaser.Scene`
- `layers: LayerRegistry`
- `pools: DisplayPoolRegistry`
- `textureManager: TextureManager`
- `pulseEngine: PulseEngine`
- `spec: DisplaySpec`
- `scratch: DisplayScratch`
- `selectedEntityId: string | null`
- `selectEntity(id: string | null): void`

`DisplayTickContext`:
- all init fields plus:
- `timeMs: number`
- `deltaMs: number`
- `pulseValue: number`

`DisplayDestroyContext`:
- `scene`, `layers`, `pools`, `textureManager`, `pulseEngine`, `spec`, `scratch`

#### 7.1.4 Module model (dumb functions)
`DisplayModuleFactory`:
- `id: string`
- `create(ctx: DisplayInitContext): DisplayModuleRuntime`

`DisplayModuleRuntime`:
- `id: string`
- `tick(ctx: DisplayTickContext): void`
- `destroy(ctx: DisplayDestroyContext): void`

#### 7.1.5 DisplayDefinition and registry
`DisplayDefinition`:
- `display_key: string`
- `moduleStack: DisplayModuleFactory[]` (ordered; may be empty)

`DisplayRegistry`:
- `register(def: DisplayDefinition): void`
- `resolve(display_key: string): DisplayDefinition` (always returns a definition)
- `clear(): void`

Fallback rule:
- Unregistered keys resolve to the default placeholder definition; logging behavior defined in §12.2.

## 11. Placeholder variants (distinctness per display_key)

### 11.1 Add: `src/engine/phaser/display/placeholder/PlaceholderVariantRegistry.ts`
**Responsibility:** Deterministically map `display_key` → placeholder variant.

Types:
- `PlaceholderVariant`:
  - `texture: TextureKeys`
  - `rotation: 0 | 90 | 180 | 270`
  - `flipX: boolean`

Interface:
- `get(display_key: string): PlaceholderVariant`

Rules:
- Deterministic: same key -> same variant.
- Unique assignment until capacity exhausted:
  - for up to `variants.length` unique keys encountered, each gets a unique variant
  - after exhaustion, reuse is allowed and a loud log is emitted once per new key beyond capacity

Variant list is explicit and finite:
- It is constructed from:
  - a fixed list of TextureKeys intended for placeholders (e.g., TRIANGLE, STAR, OCTAGON, PLUS, HEXAGON, etc.)
  - combined with rotation and flipX options
- The exact list and ordering are defined in this file (not elsewhere).

## 13. Modules (optional building blocks; placement via layers/anchors)

All modules are factories producing runtime `{tick, destroy}` functions.

### 13.1 Add: `TransformModule`
File: `src/engine/phaser/display/modules/TransformModule.ts`

Responsibility:
- Update positions and visibility for all instance anchors each tick.

Tick rules:
- If `spec.hasPhysics` is false:
  - set all anchors (root/background/effects/overlay) to invisible.
- Else:
  - set all anchors visible.
  - set each anchor x/y to spec x/y.

Destroy:
- no pooled objects are released here (anchors released by instance destroy).

### 13.2 Add: `BackgroundModule`
File: `src/engine/phaser/display/modules/BackgroundModule.ts`

Responsibility:
- Provide a background image behind the entity using the backgroundAnchor (replaces TransferScene backgroundSprites behavior).

Create:
- acquire Image from per-display-key pool (`DisplayTypePool.imagePool`)
- parent it under `scratch.backgroundAnchor`
- store in `scratch.backgroundImage`

Tick:
- If `spec.radius` is not visible (using existing visibility predicate): hide backgroundImage.
- Else:
  - choose background texture key:
    - if styleId resolves and style shape is available: map circle/rect/hex to TextureKeys
    - else default to TextureKeys.CIRCLE
  - set texture and scale to match spec radius (relative to TextureManager standard size)
  - show backgroundImage

Destroy:
- detach from backgroundAnchor
- release to pool
- set scratch.backgroundImage = null

### 13.3 Add: `PlaceholderShapeModule`
File: `src/engine/phaser/display/modules/PlaceholderShapeModule.ts`

Responsibility:
- Draw the distinct placeholder marker using `scratch.root` and placeholder variant registry.

Create:
- acquire Image from per-display-key pool
- parent it under `scratch.root`
- store in `scratch.mainImage`

Tick:
- If not visible: hide mainImage.
- Else:
  - variant = PlaceholderVariantRegistry.get(spec.display_key)
  - apply texture, rotation, flipX
  - scale to a deterministic fraction of spec.radius (constant in module file)
  - show mainImage

Destroy:
- release mainImage to pool and null it

### 13.4 Add: `InteractionModule`
File: `src/engine/phaser/display/modules/InteractionModule.ts`

Responsibility:
- Enable click selection on the display.

Create:
- Choose target interactive object:
  - if backgroundImage exists use it; else if mainImage exists use it; else no-op with loud log.
- Set interactive.
- On pointer down, call `selectEntity(spec.entityId)`.

Tick:
- Enable/disable interactivity to match visibility of the chosen interactive object.

Destroy:
- remove handlers, disable interactivity.

### 13.5 Add: `PulseModule`
File: `src/engine/phaser/display/modules/PulseModule.ts`

Responsibility:
- Apply a simple pulse-driven effect using `ctx.pulseValue`.

Factory parameters (typed; explicit):
- `target: "root" | "background" | "main" | "effectsAnchor" | "overlayAnchor"`
- `effect: "scale" | "alpha"`
- `strength: number`
- `base: number` (baseline scale multiplier or alpha baseline)

Tick:
- Resolve target object from scratch.
- If target missing: no-op.
- Apply effect deterministically based on pulseValue:
  - scale: set scale to `base + pulseValue * strength`
  - alpha: set alpha to `base + pulseValue * strength` clamped to [0,1]

Destroy:
- reset affected property to baseline `base` if target exists.

### 13.6 Add: Particles infrastructure
Files:
- `src/engine/phaser/display/particles/ParticlesKinds.ts` (types)
- `src/engine/phaser/display/particles/ParticlesConfigRegistry.ts`
- `src/engine/phaser/display/particles/HeatParticlesConfigResolver.ts`
- `src/engine/phaser/display/particles/XpParticlesConfigResolver.ts`

Responsibility:
- Provide typed emitter configs for `heat` and `xp`.

### 13.7 Add: `ParticlesModule`
File: `src/engine/phaser/display/modules/ParticlesModule.ts`

Factory parameters:
- `kind: "heat" | "xp"`
- `particleTexture: TextureKeys`
- `placement: "anchored" | "global"`

Create:
- acquire ParticleEmitterManager from per-display-key pool.
- Set its texture to particleTexture.
- Create an emitter using config from ParticlesConfigRegistry.get(kind).
- Store manager and emitter in scratch.
- Placement:
  - anchored: parent manager under `scratch.effectsAnchor`
  - global: parent manager under LayerRegistry.get(EffectsGlobal)

Tick:
- If entity not visible: stop emission (disable emitter) and hide manager.
- Else:
  - ensure manager visible.
  - set manager position:
    - anchored: 0,0 local (since effectsAnchor follows entity)
    - global: world x/y = spec x/y (explicitly set each tick)
  - read intensity:
    - heat: from `entity.state.heat.value` if present else 0
    - xp: from `entity.state.xp.value` if present else 0
  - map intensity to emitter enabled and rate using resolver-defined mapping rules (explicit constants per resolver; no ad-hoc math in module).

Destroy:
- stop emitter, remove from parent, release manager to pool, null scratch fields.

## 14. EntityVisualInstance and lifecycle manager

### 14.1 Add: `EntityVisualInstance`
File: `src/engine/phaser/display/EntityVisualInstance.ts`

Responsibility:
- Own anchors (root/background/effects/overlay) and module runtime functions for one entity.

Create algorithm (unambiguous):
1) pool = pools.get(spec.display_key)
2) Acquire anchors from pool:
   - root, backgroundAnchor, effectsAnchor, overlayAnchor
3) Parent anchors to corresponding layer containers in LayerRegistry.
4) Initialize scratch with anchors and null object slots.
5) Resolve DisplayDefinition from DisplayRegistry.
6) For each factory in definition.moduleStack:
   - runtime = factory.create(initCtx)
   - store runtime list in order

Tick:
- compute pulseValue already supplied by manager in ctx
- call each module runtime tick in order

Destroy:
1) Call module runtime destroy in reverse order.
2) Validate scratch object slots are null:
   - if any of backgroundImage/mainImage/particlesManager/particleEmitter are non-null, log loudly and forcibly release/destroy them using pools to avoid leaks.
3) Detach anchors from layers.
4) Release anchors back to DisplayTypePool.
5) Clear instance references.

### 14.2 Add: `DisplayInstanceManager`
File: `src/engine/phaser/display/DisplayInstanceManager.ts`

Responsibility:
- Own mapping entityId → EntityVisualInstance and drive lifecycle each frame.

Inputs:
- `scene`, `layers`, `textureManager`, `pulseEngine`, `pools`, `displayRegistry`, `placeholderVariantRegistry`, `particlesConfigRegistry`
- callbacks: `getRuntime`, `getSelectedEntityId`, `selectEntity`

Tick algorithm (pseudocode):
- runtime = getRuntime()
- if runtime null:
  - destroy all instances
  - pools.destroyAll()
  - return
- seen = empty set
- for each entity in runtime.getEntities():
  - resolve blueprint (typed) from runtime.getCartridge().blueprints
  - resolve physics (typed) via runtime.getPhysicsBody(entity.id) if available
  - spec = resolveDisplaySpec(...)
  - if spec null:
      destroy existing instance if present
      continue
  - ensure instance exists (create if missing)
  - pulseValue = pulseEngine.getDemandPulse(entity.id, timeMs)
  - build tick context (includes selectedEntityId and selectEntity)
  - instance.tick(ctx)
  - seen.add(entity.id)
- destroy instances not in seen

Error policy:
- if module tick throws, catch and log loudly with entityId + moduleId; continue.

## 17. Loud error policy
- Invalid display component present but missing/empty display_key: loud log, no instance.
- Missing display definition: loud log once per display_key, fallback used.
- Placeholder variants exhausted: loud log once per new key beyond capacity.
- Module tick errors: loud log with entityId + moduleId; continue.
