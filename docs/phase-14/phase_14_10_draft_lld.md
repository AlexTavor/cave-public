Low-Level Design: Draft Pack Editor Refactor

1. Overview

This document outlines the refactoring of the .draft file editor (DraftPackEditor) from a raw JSON viewer into a user-friendly navigation dashboard. This change aligns the Draft editor with the pattern established for .cave and .art editors, providing a central hub to navigate to specific sub-editors for Draft Options and Draft Pools.

Goals

Dashboard Experience: Transform DraftPackEditor into a navigation menu with clear call-to-actions.

Seamless Navigation: Integrate with the existing window manager routing to open "Draft Options" and "Draft Pools" in separate, dedicated tabs.

Component Resolution: Ensure the window layout system correctly maps internal routing IDs to the specific React components for draft management.

2. Architecture & Components

2.1. Draft Pack Dashboard (DraftPackEditor.tsx)

Responsibility:
Serves as the root UI for a .draft file tab. Instead of showing JSON, it renders a high-level menu directing the user to specific editors within the module.

Logic:

Container: Uses ToolFrame to provide a consistent window header and toolbar.

Navigation Actions: Uses useShellStore to access the openFile action.

Layout: Renders a grid of Card components.

Draft Options Card:

Label: "Draft Options"

Description: "Configure discrete events and choices."

Interaction: Triggers openFile("options::{filename}").

Draft Pools Card:

Label: "Draft Pools"

Description: "Manage weighted probability pools."

Interaction: Triggers openFile("list::{filename}::draft_pools").

Interface:
No changes to props ({ filename: string }).

2.2. Window Layout Resolution (WindowLayoutResolver.editors.tsx)

Responsibility:
Maps the string identifiers used by the FlexLayout nodes (generated by route handlers) to the actual React component instances.

Changes:
The resolver currently handles file types and some list types. It must be updated to explicitly handle the specific component IDs generated by the useWindowManagerRouteHandlers for drafts.

Mapping Logic:

draft_options → Renders DraftOptionsPanel with filename.

draft_pool_list → Renders DraftPoolListPanel with filename.

draft_pool_editor → Renders DraftPoolEditor with filename and poolId.

Note: While WindowLayoutResolver.draft.tsx exists in the imports, standardizing these panel mappings within the main WindowLayoutResolver.editors.tsx (where other lists and editors live) ensures consistency and easier discovery.

4. Verification & Testing

4.1. Manual Verification Steps

Open a .draft file from the explorer.

Expectation: See the new Dashboard with "Draft Options" and "Draft Pools" cards instead of JSON.

Click "Draft Options".

Expectation: A new tab "Draft Options" opens.

Click "Draft Pools".

Expectation: A new tab "Draft Pools" opens (showing the list of pools).

In the "Draft Pools" list, click "Open" on a specific pool.

Expectation: A specific "Draft Pool: [ID]" tab opens.
